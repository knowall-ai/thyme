= Thyme Troubleshooting Guide

Common issues and their solutions. Add new entries as problems are discovered and resolved.

|===
| Problem | Solution

| Auth redirect fails with "AADSTS50011" error
| Verify redirect URI in Azure App Registration matches `NEXT_PUBLIC_AZURE_REDIRECT_URI` exactly (including trailing slash if present)

| BC API returns 401 Unauthorized
| Check that BC API permissions are granted admin consent in Azure; verify token hasn't expired

| BC API returns 403 Forbidden
| User needs appropriate Business Central license and permissions assigned

| Projects dropdown is empty
| Verify `NEXT_PUBLIC_BC_COMPANY_ID` and `NEXT_PUBLIC_BC_ENVIRONMENT` are set (must have `NEXT_PUBLIC_` prefix for client-side access); check that `/projects` endpoint returns data (not `/jobs`)

| Team page shows no employees, or a person is missing from Team/Reports
| Thyme lists resources that are a Person, not blocked, use time sheets and have a Time Sheet Owner User ID set on the Resource Card in BC. Open the person's Resource Card and check *Type* = Person, *Blocked* is off, *Use Time Sheet* is on and *Time Sheet Owner User ID* is filled in. Placeholder role resources used only for estimates (no Time Sheet Owner) are deliberately left out.

| Team tab shows 0 hours for everyone during summer time
| Upgrade to the latest Thyme version. Earlier versions looked up each person's timesheet with the week start converted to UTC, which in timezones ahead of UTC (e.g. UK summer time, BST) is the previous day (Sunday), so no timesheet matched and every person showed 0 hours. The same fix stops a custom date range on the Approvals page being stored one day early.

| Team page shows no billable targets (no "/ 75% default" next to Billable %, no "Billable vs target" card), and Settings has no Billable Target section
| Billable targets need a Thyme BC Extension version with billable targets (the `billableTargetPercent` / `billableTargetSet` fields on the resources API and the `thymeSetup` API). Install the latest extension in the BC environment; older versions keep working, just without targets.

| "You don't have permission in Business Central to change billable targets" when saving a target
| Business Central refused the change (403). Billable targets are saved to the Resource (per person) and Thyme Setup (company default) in BC, so the user needs permission to modify those records; ask a BC administrator to assign it, or to change the target for you.

| Team page "Timesheet completion" is below 100% for someone who worked a full week
| Timesheet completion is hours logged ÷ capacity. Check their timesheet for missing days, and that their capacity is right: it comes from the hours per day on the person's resource units of measure in BC (e.g. a DAY unit of 7.5 hours), falling back to 40 hours a week.

| Timer state lost on refresh
| Check browser allows localStorage; timer state persists in localStorage

| "missing required error components" on page load
| Clear `.next` folder and restart dev server: `rm -rf .next && npm run dev`

| Sign-in popup blocked
| App now uses redirect flow; if still seeing popups, clear cache and rebuild

| Logout doesn't work
| Verify `postLogoutRedirectUri` is set to `/` in AuthProvider; check for console errors

| TypeScript build errors after changes
| Run `npm run build` to see full errors; check that new types are exported from `src/types/index.ts`

| Tailwind classes not applying
| Ensure file is in `content` array in `tailwind.config.js`; avoid dynamic class string interpolation

| vitest/vite version conflict
| `vitest.config.ts` should be excluded in `tsconfig.json` exclude array

| Dev server on wrong port
| Ports 3000/3001 may be in use; check console output for actual port (e.g., 3002)

| BC API returns 404 on endpoint
| Verify the endpoint exists in BC API v2.0; some entities use different names (e.g., `projects` not `jobs`)

| Production auth fails with "AADSTS900144: client_id missing"
| `NEXT_PUBLIC_*` env vars are baked in at build time in Next.js, not runtime. Add them as GitHub secrets and include in the build step of `deploy-production.yml` workflow. Azure App Service settings alone won't work for client-side variables.

| "No Timesheet Available" message shown
| A timesheet must be created in BC before users can enter time for a week. Contact your timesheet manager to create timesheets for you. See Issue #61 for manager timesheet creation feature.

| "Thyme BC Extension is not installed" error
| The Timesheet API requires the Thyme BC Extension to be installed. Install from https://github.com/knowall-ai/thyme-bc-extension

| Timesheet shows as read-only
| Timesheets become read-only once submitted for approval. If rejected, click "Reopen for Editing" to make changes.

| Time entries not saving
| Ensure you have an Open or Rejected timesheet for the week. Submitted and Approved timesheets cannot be edited.

| "Could not find your resource record" error
| Your user account must have a matching Resource record in BC with a valid email address. Contact your BC administrator.

| "Resource Record Not Found" but BC extension check passes
| The extension's `/resources` API endpoint may not exist. This happens when using an older extension version or when the extension isn't fully installed. Reinstall the latest Thyme BC Extension from https://github.com/knowall-ai/thyme-bc-extension

| "Poppie's suggestions" panel doesn't appear under the week on the Time page
| The panel only shows when the Thyme BC Extension has the `timeSuggestions` API; with an older extension it is hidden. Upgrade to the latest Thyme BC Extension from https://github.com/knowall-ai/thyme-bc-extension. If the panel shows but stays empty, Poppie hasn't written any suggestions for that person and week yet, or a suggestion matches an entry already in the week (those are hidden).

| Poppie's suggestions show but have no Add button
| Suggestions can only be added to an open (or rejected) timesheet of your own. Reopen a submitted timesheet first; approved timesheets and teammates' timesheets are read-only, and the panel says why.

| "No Approval Access" on Timesheet Approvals page
| To approve timesheets, configure the approver in Business Central: (1) *Make user a Time Sheet Admin:* Search for "User Setup" → find your user (or create a new entry) → check the "Time Sheet Admin" checkbox. This allows the user to approve any timesheet. (2) *Or link approver to specific resources:* Search for "Resources" → open each Resource Card for employees you manage → set "Time Sheet Approver User ID" to your BC user ID. This allows you to approve only timesheets for those specific resources.

| Azure managed SSL certificate fails with "A record must point to..."
| Azure App Service managed certificates require a proper A record for root domains, not a CNAME or ALIAS. Configure DNS with an A record for `@` pointing to the App Service IP shown in the error message. CNAME records are technically not allowed on root domains by DNS standards. The `www` subdomain can use a CNAME pointing to your App Service hostname.

| Hours and days display incorrectly (e.g., 12h shows as 12d instead of 1.5d)
| Resources with Base Unit of Measure = DAY need an HOUR unit configured for conversion. In BC: (1) Open the Resource card (2) Go to Related → Resource → Units of Measure (3) The DAY row must stay at Qty per Unit of Measure = 1 (base unit, cannot change) (4) Add a new row for HOUR with Qty per Unit of Measure = 0.125 (for 8-hour days) or 0.133 (for 7.5-hour days). This tells BC that 1 HOUR = 0.125 DAYs. Thyme reads these conversion factors from the `/resourceUnitsOfMeasure` API (requires BC Extension v1.7.0+).

| "You don't have permission to rename projects in Business Central" when renaming a project
| Renaming saves the project's Description to the BC Job, so your BC user needs Modify permission on the Job table. Ask your BC administrator to assign a permission set that allows editing projects (e.g. one that includes `JOBS-ALL` or a custom set with Modify on TableData Job), then try again. The name stays as it was until the save succeeds.

| A project priced in another currency (e.g. EUR) shows the company currency (e.g. £) on Billable Price, Invoiced Price or the Spend vs Budget chart
| Thyme shows customer prices in the project's *Currency Code* (from the BC Project card) and internal costs (Budget Cost, Actual Cost) in the company's currency. It reads the project currency from Thyme BC Extension 1.14.0.0 or later; with an older extension every amount is labelled with the company currency, as before. Use 1.14.0.1 or later: on 1.14.0.0, planning lines created through the API (e.g. from Thyme's Plan) on a project in another currency are priced in the company currency but labelled with the project's, so recreate any such lines after updating. Update the extension in BC, then reload the project. If the project should be in the company currency, clear *Currency Code* on the Project card.

| Internal time shows as billable in Reports (or a customer project's time shows as non-billable)
| Thyme counts time as billable only if its project isn't internal and the timesheet line isn't marked not chargeable. A project is internal when it has no Bill-to Customer, or its Bill-to Customer's name contains the whole word "Internal" (e.g. "Contoso - Internal"; "Contoso International" doesn't count). In BC, open the Project card and check *Bill-to Customer No.*: give internal projects an internal customer (or leave it empty), and make sure customer projects are billed to the real customer. A customer named e.g. "Internal Audit Ltd" would also be treated as internal, so rename it or bill the project to another customer. Lines with *Chargeable* unticked on the timesheet are never billable.

| "Poppie's recommendation" never appears on the Approvals or Time page
| The panel only shows when the Thyme BC Extension has the `timesheetReviews` and `timesheetReviewLines` API pages; on an older extension Thyme hides it (the browser console shows "timesheetReviews endpoint not found"). Update the extension in BC. If the panel says "Awaiting Poppie's review…" for more than about 10 minutes, check that Poppie's review job is running and can reach the company: Thyme only reads reviews, it doesn't create them.

| Poppie's review says "Out of date"
| The timesheet's lines or daily hours were changed after Poppie reviewed it (Thyme compares their latest modified time with the review's version stamp). Once the timesheet is submitted again, Poppie re-reviews it on her next pass and the panel updates by itself; no action is needed.

| A link opens with "You don't have access to that company in Business Central"
| Thyme URLs include the environment and company (`/production/{companyId}/projects/...`), and the link points at a company your account can't see. This happens when the company is in an environment you don't have (e.g. a Sandbox), or your BC user hasn't been given access to that company. (1) Ask your Business Central administrator to give your user access to the company in that environment, then sign out of Thyme and back in. (2) Or click *Go to …* to open the same page in your current company instead.

| A shared Thyme link shows "This page could not be found"
| The URL must be `/{environment}/{companyId}/{page}`, where the environment is `production` or `sandbox` and the company ID is the BC company GUID (e.g. `/production/00000000-0000-0000-0000-000000000001/plan`). A truncated or hand-edited link won't match; copy the link again from the browser's address bar. Old links without a company (e.g. `/projects/PR00100`) still work and open in your current company.

|===
